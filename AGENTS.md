# Repository workflow

- Read `docs/DEVELOPMENT_PLAN.md` and the latest `docs/PROGRESS.md` handoff before changing code. Inspect the actual branch, commit, local changes, and applicable instructions; the reviewed SHA in the plan is a reference only.
- Work in small, reviewable slices. Verify the relevant behavior, inspect the diff, and update the plan and progress record in the same change. Check a task only after its stated acceptance criteria pass. Preserve task IDs and log material scope or dependency changes.
- Run routine development with `fixtures/synthetic-input.json`, `npm run dev:demo`, and mocked providers. Never use real usernames, viewing histories, private ratings, salts, or credentials in fixtures, logs, screenshots, tests, or commits.
- Do not fetch or regenerate production datasets, expand collection, publish data or models, route imports through a new third party, deploy, or add paid infrastructure without the relevant authorization. Keep the existing TypeScript, Python, and Rust stacks unless evidence and an approved product decision justify a change.
- Check `docs/decisions/0001-provider-data-permissions.md` before any MAL, AniList, or Jikan dependent work. Its unresolved source/use cells are holds for collection, retained caches, training, and public artifacts; continue with synthetic fixtures and mocked providers. A working public endpoint or pseudonymous ID does not clear those holds.
- For GitHub Actions retraining, data release, and Pages deployment, follow `docs/decisions/0002-provider-workflow-gates.md`. Keep use-specific repository approval variables unset until a reviewed source/use decision and owner approval are recorded. Run the synthetic gate tests and fixture PR checks; do not dispatch production jobs to test a gate.
- The compact v1 graph's optional fourth anime-pair tuple value is co-rater support. Its weight remains the mean of two user-centered scores, a pair-preference statistic, not correlation or item similarity. [Decision 0005](docs/decisions/0005-graph-edge-semantics.md) selects support-shrunk adjusted cosine for a future recommendation neighborhood; its scorer and invented benchmark are not wired to exports or consumers. [Decision 0006](docs/decisions/0006-signed-graph-evidence.md) keeps negative/zero pair preference visible with its sign but excludes it from graph recommendations and attractive model regularization; only positive weights contribute there. [Decision 0007](docs/decisions/0007-bounded-pair-selection.md) selects pair edges from exact statistics inside separate visit/key budgets; budget exhaustion fails before export. [Decision 0008](docs/decisions/0008-seeded-per-user-selection.md) selects a capped user's ratings by recorded seed/hash and records omissions and process measurements. [Decision 0009](docs/decisions/0009-graph-v2-contract.md) versions current semantics, configuration, truncation, and dataset identity in v2 recommendation exports and separates a linked explorer sample. Keep v1 readers valid; require matching v2 graph roles and provenance; never substitute the visualization sample for ranking or training. M5 split-first evaluation remains before wiring signed similarity into runtime consumers.
- When changing graph, catalog, or model producers or loaders, update `web/src/artifacts.ts` runtime contracts and the synthetic unit/browser tests together. A present unsupported or malformed artifact should fail with its file and field identified; keep missing-file legacy fallback deliberate.
- Recommendation indexes, scoring, candidate/metadata eligibility, and explanation text live in `web/src/recommendations.ts`. Characterize current outputs with synthetic unit and browser tests before changing ranking semantics; decision 0006 settles v1 negative pair-preference use, while M4.1 owns signed user preference and M4.6 owns blend endpoints.
- Use `createCandidateEligibilityPolicy` and `rankEligibleCandidates` for graph, model, hybrid, and fallback results. Include Only intersects the active ranking's candidates; it never inserts a title into graph or model results, and it narrows the catalog baseline when that engine is active. Explicit exclusions, all watched preferences and imported seen history, missing graph-catalog entries, and required genre/year/score checks take precedence. Check eligibility before hybrid normalization and again before display. Model failures or empty mapped output fall back to eligible graph results, then the labeled positive-connection catalog baseline; keep the requested mode setting and report the actual engine. Treat the baseline as a failure path, not M4.4's evaluated cold-start solution. Keep metadata prefetch limits and missing-data coverage visible; M6.4 owns broader catalog completeness.
- Browser data reads and local state use `web/src/artifact-loader.ts`, `web/src/providers.ts`, and `web/src/persistence.ts` with injected `RuntimePorts`. Use fake transport/storage/clock and seeded randomness in routine tests; keep provider scheduling changes in M2.4.
- Recommendation state and named profiles now use version 5 browser keys with explicit `seen`, `liked`, and `disliked` preferences, importance, confidence, and source. Preserve untouched `wasiw.*.v1` and `.v4` sources and exact raw backups during migration; keep unknown catalog IDs, importance, and overrides visible and round-trippable. Default manual additions to Seen. After native-scale conversion, scores at or below 4/10 are Disliked, above 4 and below 7 are Seen, and 7 or above are Liked; an unscored watch is Seen and a planned title contributes no preference. A user's manual choice wins over a later import. Test corrupt and quota-rejected storage with injected ports, and show write failures rather than claiming a profile was saved. M6.6 owns full export/import, merge preview, reset, and recovery controls.
- Async imports and metadata requests receive `AbortSignal`s and guard every delayed result before changing watched state, metadata caches, or status text. A profile or recommendation-state change cancels obsolete work; local `File.text()` reads use a generation guard. Keep loading, empty, unavailable, failed, stale, and demo statuses distinct in the UI and mocked-provider tests. M2.4 still owns provider-wide rate scheduling, timeouts, `Retry-After`, and retry budgets.
- Treat catalog, provider, profile, graph, and imported strings as untrusted at every UI sink: use `textContent` or escape HTML text/attribute values, and pass image references through `safeExternalImageUrl` before rendering. Keep synthetic markup and rejected URL regression cases; do not use a real user's history for them. Verify source usage before removing dependencies, then check the lockfile with a clean install, npm audit, and the fixture/browser gates.
- Route browser AniList/MAL/Jikan reads through the shared TypeScript `ProviderScheduler`; route TypeScript crawler calls through its single process-local scheduler and Python Jikan feature reads through `JikanRequestScheduler`. Follow [decision 0003](docs/decisions/0003-provider-request-policy.md) for source limits, `Retry-After`, timeout/cancellation, and the per-runtime boundary. Test changes with injected clocks, transport, and randomness; never make a real provider call to validate a rate policy. Decision 0001's use/collection holds still apply.
- Route crawler list pages through `collectUserSnapshot` with an anonymized ID and a mocked `MalPageFetcher` in tests. Full pages persist only as checkpoints; a validated nonempty short terminal page replaces one user's raw and normalized ratings in one transaction. Keep last complete ratings on timeout, cancellation, empty/private, malformed, or capped pages. Check `collection_status` outcomes and resume offsets, and test changed scores and removed entries before changing this path. The MAL site route has no snapshot version; do not claim time-consistent provider data or lift decision 0001's collection hold.
- Keep SQLite schema changes in the transactional `user_version` migrations and verify both the unversioned legacy and M2.5 checkpoint layouts before adding columns. Never fill unknown old source IDs or timestamps with guesses. New collection rows record source route/item ID, local `fetched_at`, a fetch run, and `normalized_field_version`; only a provider-documented adapter may supply `provider_updated_at` through `VerifiedProviderPage`. Local fetch/commit times are not viewing or rating times. Follow [decision 0004](docs/decisions/0004-collection-provenance.md), retain per-run status tests, and keep raw usernames out of SQLite and logs. Provider rights remain held by decision 0001.
- Keep imported history in `web/src/import-history.ts` separate from explicit preferences in `web/src/preferences.ts`. Persist source identity, raw status, episode progress, native score and scale, including unscored and catalog-missing items, in browser state and profiles. Seen titles exclude candidates without seeding ranking; only likes seed the current positive-only pair graph, while the existing model consumes signed like/dislike evidence. Do not treat negative v1 item-pair preference as a dislike. AniList mocks declare the user's score format; do not force a 10-point response and label it native. Preview every file and mocked username import before an explicit merge or replace; replace also clears current watched picks, so show its removal counts. Seasonal browsing must not write watched or liked history. Parse only the documented local `.txt` and bounded MAL-style `.xml` subset, reject DTDs/invalid fields, and retain old state on cancellation or storage failure. Use invented data and mocked provider responses in tests; the M2.1 provider-use hold still applies to live requests and deployment.
