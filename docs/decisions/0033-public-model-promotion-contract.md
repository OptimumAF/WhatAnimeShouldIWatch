# 0033 — Public model promotion follows a verified aggregate data bundle

**Status:** M8.4 contract and invented compatibility checks, 2026-09-28. This decision authorizes synthetic and mocked development only. It does not approve a model, a source, publication, deployment, or a release workflow dispatch.

## One versioned bundle

Promote a model by creating a new immutable `data-v...` release bundle whose manifest names an already approved, separately verified aggregate-only v3 data bundle as `lastKnownGood`. Copy the prior bundle's recommendation graph, explorer graph, and identity catalog **byte-for-byte**. Add one item-only `model-mf-compact-v1` asset and a new manifest that binds its bytes, declared dataset, item IDs/titles, and coverage. The browser must rank the v3 graph and model from the same pinned bundle; a data-only bundle must continue to have no model fallback from legacy paths. A model promotion cannot regenerate, replace, or expand the data snapshot as a side effect. A changed data snapshot requires its own M8.3 review and release first.

The public model JSON may contain only its documented item IDs, titles, biases, embeddings, global mean, factor count, generated time, and optional documented provenance/count fields. Reject extra fields at the browser and manifest boundary so training-user factors, user mappings, histories, and private refit state cannot hide in a valid model asset. The old compact and legacy readers remain valid for their documented fields. The eventual model release package needs an exact allowlist for the five manifested files plus a separate model-promotion audit. No numeric training archive, user factors, raw ratings, refit rows, or full evaluation report belongs in its public assets. The current M8.3 data-only publisher remains data-only; it must never silently accept this model package.

## Evidence and approval bridge

The existing `model-promotion-v1` preflight checks a private v2 graph and demo catalog. It does not establish compatibility with the public v3 graph/identity catalog, permission to release a model, or a deployment trigger. Keep its invented tests and read-only purpose, but introduce a separate versioned promotion record for the v3 release path. That record must bind the exact base and candidate bundle IDs/manifests, unchanged data asset hashes, model bytes and numeric archive digest, frozen selection and final refit, the one-use final report's exact hash, a reviewed dataset-identity bridge from permitted raw training snapshot to the v3 graph, predeclared serving-path quality/latency/coverage gates against the best simple baseline, mapping/coverage floors, source/use decision references, and an owner decision on the exact candidate. A self-declared model `datasetSha256`, boolean quality claim, authored synthetic win, or retrain upload alone cannot satisfy those gates.

The promotion route must remain separate from periodic retraining. An approval-gated verifier should consume a pinned private candidate and committed exact-bundle approval, then pass only public allowlisted bytes into a write-permission release job. Before mutation, require source/use approvals for training, publication, and deployment as applicable, an approved immutable base release, repository immutable-release setting, and an absent target tag/release. Reverify before upload and compare remote immutable asset digests afterward. A failure must leave the prior bundle available. No current approval registry entry or provider-use approval exists.

Only after the immutable model release passes remote verification may a promotion request trigger an exact-tag Pages build through M8.5's verified installer and hosted checks. The trigger must carry the tag and manifest digest; the current `deploy-web.yml` fetches mutable `data-latest` and cannot serve as that trigger. An Actions artifact from weekly retraining is an experiment output until this entire path passes. M8.4 and M8's exit gate remain unchecked; M8.5 and M8.7 own hosted verification and practiced recovery.

## Local package and independent review boundary

The M8.4 local packager accepts a five-file model-bearing v3 candidate, a separate data-only v3 base, and a private evidence directory. It verifies the candidate's `lastKnownGood` pointer and manifest, compares the graph, explorer, and identity catalog bytes exactly with the base, requires an item-only model and bounded exact file inventories, and writes a new six-file package through a temporary directory. The public package contains only the five release files and `model-promotion-audit.json`. It excludes the numeric archive and its user-ID-bearing metadata sidecar, frozen selection, final report, one-use marker/digest, refit record, dataset bridge, quality policy, cohort, and serving report. Invented packages are marked `synthetic-only`; a nonfixture package is only `pending-approval`, never self-approved.

The separate `model:release:package:check` command recomputes all six bytes from private evidence. For a nonfixture package it requires a separate restricted source directory with exactly `raw-ratings.json`, `split-manifest.json`, and `anime-metadata.json`. It checks the committed empty-by-default `model-release-bundles.json` registry and training/publication/deployment source-use records against the package audit **before** reading private rows, then checks the exact approved data-base package and its separate approval. A registry entry binds the candidate/base IDs and byte hashes, source run and artifact name, bridge review, private sidecar digest, quality policy, serving report, and a distinct owner approval. Invented tests inject temporary reviews to exercise the positive path and stale or missing approval refusals; the executable uses the committed empty registries and cannot approve a real package today.

The packager now calls a read-only evaluator that recomputes a bound private report from the candidate's v3 recommendation graph, item model, identity catalog, private metadata/cohort, and quality policy. The evaluator uses the browser's score-to-preference mapper, graph/model/genre/catalog scorers, central eligibility and ranking, and final franchise selector. A synthetic score-independent hash chooses each evaluation user's observed prefix. Fit IDs, baseline-validation users, and final-test users must be disjoint. Only the validation group selects the best of graph, exact-genre overlap, and positive-connection catalog coverage; a declared baseline that differs from that winner fails. The final group compares that baseline with model-only ranks on the same eligible positive labels. The report contains aggregate binary NDCG@K, unique displayed-title coverage over the centrally eligible catalog union, user/positive counts, and local batch p95 latency. The review names a public model-map coverage floor; the policy separately names a serving coverage floor. Neither is a probability or a real-audience estimate. The evaluator checks validation and final sample floors, NDCG lift, serving coverage, and recorded plus freshly measured latency ceilings. A rehashed report with an invented favorable metric fails recomputation. The packager rereads all inputs after evaluation before staging public bytes.

The private archive gate uses the existing numeric-only NPZ reader with pickle disabled, exact array membership, dtypes, shapes, finite values, packed-index bounds, and the hash-bound `model.metadata.json` sidecar. The refit record now binds that sidecar's bytes. Before packaging, recompute the fitted-array fingerprint and packed fit-row count, require its fit-user ID set to equal the private serving cohort's training users, and reproduce the compact item's IDs, titles, global mean, biases, and embeddings at the refit's eight-decimal export precision. Both the exact approval and public audit bind the sidecar digest, never the sidecar contents. Tests use an actual invented NPZ and reject rehashed changed arrays, changed item values, mismatched users, and count drift. The separate v2 private preflight remains read-only for its older contract.

The cohort, labels, metadata, policy, sidecar, and detailed report remain private and hash-bound; only their digests enter the public audit. This invented fixture establishes executable consistency, not a production quality result. Exact packed archive fit-user/item membership is checked against validated raw fit rows, and split-first parameter reproduction is separately required. [Decision 0035](0035-serving-evaluation-freeze.md) adds an earlier private byte/policy freeze, one-use final parsing, and a prior committed owner approval for recorded chronology. It cannot prove no unrecorded experiment preceded that approval. Local p95 excludes network and browser rendering and varies by host. Model-only ranks deliberately expose the model signal without masking it through fallback; the complete hosted behavior and model failure route still need M8.5 checks. An owner must review permitted source lineage, frozen split/cohort and policy, numeric archive integrity, selection and final report, rights/privacy basis, and the exact candidate before recording a real approval. A production route additionally needs immutable GitHub release preflight, a six-file upload/post-upload digest check, an exact-tag deployment trigger, hosted checks, and rollback practice. No workflow uses this package yet.
