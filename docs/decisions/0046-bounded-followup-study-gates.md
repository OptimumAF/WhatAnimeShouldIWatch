## Windows OS ports — 2026-10-07 (partial)

`createWindowsFollowupPorts` now provides real private inspection and exclusive reservation through a fixed local Windows PowerShell helper. It uses argument arrays, a hidden noninteractive process, the built-in Windows PowerShell module path, and bounded timeout/output. It changes neither execution policy nor ACLs, creates no study directory, reads no pilot contents, and has no network or acquisition entry point. Non-Windows use and helper errors fail with a fixed redacted message.

The helper accepts only bounded normalized drive paths, rejecting device/stream/UNC syntax and trailing-dot/space aliases. It opens existing repository/private-parent ancestors in order with `OPEN_REPARSE_POINT` and without delete sharing, rejects any reparse/non-directory or mismatched final handle path, and holds the handles through reservation and flush. Reservation performs its own fresh pinned inspection, so an intervening target, pilot or junction is refused. [Microsoft's CreateFile documentation](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) defines those directory/reparse and sharing flags. These checks protect the path operation; they are not a defense against malicious same-owner or administrator processes, which can alter security or deliberately remove consumption records.

`verified-owner-only` now has an explicit conservative Windows meaning: the private parent's owner must be the current process SID, its DACL must be protected, and the owner must have full control applying to the directory and inheriting to files/subdirectories. Reject every deny ACE, unknown principal and nonprivileged group grant; allow only that owner, SYSTEM and built-in Administrators. Those two privileged principals are part of the local OS trust boundary, not additional ordinary users. This whitelist is stricter than merely claiming POSIX mode bits or reproducing inherited ACLs; unsupported descriptors fail closed. [Get-Acl documentation](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-acl?view=powershell-7.6) describes the security descriptor. The adapter never fixes permissions silently; a noncompliant real parent remains held for explicit review.

The durable marker is the fixed private-parent file `wikidata-followup-101-200-v1.reserved.json`, separate from deletable study outputs. `FileMode.CreateNew` with no sharing prevents overwrite and admits one concurrent winner; write-through and `Flush(true)` persist the bounded record after checking its inherited file ACL. An existing, corrupt, interrupted or partially written marker is consumed without being parsed, repaired or deleted. Any failure after creation leaves it present. [Microsoft FileMode documentation](https://learn.microsoft.com/en-us/dotnet/api/system.io.filemode?view=net-9.0). The marker contains only gate format/study/scope/approval digests, start/expiry, started state and prohibited publication; no source bytes, mappings, owner SID or resolved path. Preserve this minimal consumption metadata independently of source-output cleanup and the closed approval history; it is not a retained source cache or permission to keep source material beyond expiry.
