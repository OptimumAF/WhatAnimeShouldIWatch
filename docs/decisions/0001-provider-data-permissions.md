# 0001 — Provider data permissions and public/private boundary

**Status:** Active engineering gate, reviewed 2026-09-24. This records what the public provider documents establish for this repository. It does not grant rights that the documents leave unclear.

## Decision

Keep ordinary development on invented fixtures and mocked providers. Keep a person's explicitly selected local file and their saved recommendations in that browser. Do not start or expand provider collection, build a provider-derived public catalog, train on provider-derived histories, or publish/refresh data or model artifacts until the specific source and downstream use are cleared. A public page or a functioning endpoint is not a redistribution or training license. Review existing public assets under M2.2; this decision does not delete or republish them.

The product has a watched list and saved profiles, so its status under AniList's competing list/tracker restriction is unresolved. The existing MAL `load.json` path is a site endpoint, not the [documented MAL API v2 user-list operation](https://myanimelist.net/apiconfig/references/api/v2#operation/users_user_id_animelist_get). Jikan is an unofficial MAL scraper and does not supply upstream MAL rights. These findings block claims that any of those paths is already cleared for broad collection, caching, redistribution, or training.

## Data boundary in this repository

| Boundary | Current evidence | Required handling |
|---|---|---|
| Local person-controlled state | `web/src/main.ts` saves selected anime, weights, and named profiles in browser `localStorage`; M2.3's `.txt` picker reads the chosen file in the browser and requires review before import. | Keep file contents and usernames out of telemetry, fixtures, test logs, and public artifacts. A full delete/export workflow and status fidelity remain M2.8/M6.6. The simple `.txt` parser is not a provider export parser. |
| Restricted collection and training | `pipeline/src/anonymize.ts` creates a stable salted 24-character hash of a username. `db.ts` and `build-graph.ts` retain per-user ratings and user-anime edges. `ml-retrain.yml` downloads ratings from the public release and trains weekly. | Treat hashed IDs, raw/normalized scores, edges, and user factors as potentially linkable histories, not anonymous public data. Keep restricted inputs and outputs off public releases; require documented lawful source, scope, provenance, retention, and deletion/rebuild handling before training. |
| Public delivery | The [`data-latest` release](https://github.com/OptimumAF/WhatAnimeShouldIWatch/releases/tag/data-latest) lists `anonymized-ratings.compact.json.gz`, `graph.compact.json.gz`, and a model file. `publish-data-release.yml` can refresh these; `deploy-web.yml` fetches the release; `sync-web.ts` excludes the ratings file from the web build by default but still includes the graph and model. | The completed [M2.2 payload audit](../audits/public-artifacts-2026-09-24.md) confirms public per-user rating rows and graph edges and proposes an item-level allowlist. Handling existing copies still requires an owner decision. |

## Unblocking evidence and operational rule

1. Record provider approval, an applicable API/client agreement, or a reviewed license for each intended route and use. Specifically resolve MAL site extraction versus API v2, AniList's complementary-service status and storage rule, and Jikan's missing terms plus MAL upstream rights. Record commercial status if it changes.
2. For each approved source, define allowed fields, cache duration, source notice/attribution, image rights, rate policy, public artifact contents, training scope, retention, and deletion/correction procedure. Re-review on material provider-term changes.
3. Until then, do not invoke the existing MAL collection/expansion commands, Jikan content-feature harvesting, provider-derived model training or release publication as part of development. Do not promote their existing release assets or deploy a new bundle that depends on them. The [M2.9 workflow gate](0002-provider-workflow-gates.md) is proposed for the scheduled retrain, release, and Pages jobs; it takes effect only when merged. M8.4 still owns full model-promotion controls. Fixture generation, mocked-provider tests, local recommendation work, and source review can proceed.

**Evidence limit:** This decision is a source-and-code review and did not query real usernames. It does not claim that previously published assets are safe or that optional live provider imports are authorized. The separate [M2.2 audit](../audits/public-artifacts-2026-09-24.md) inspected public payloads read-only; remediation remains unresolved.
