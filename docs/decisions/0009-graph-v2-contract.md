# 0009 — Versioned graph provenance and separate explorer sample

**Status:** M3.7 synthetic implementation, 2026-09-25. This decision changes artifact format and selection visibility. It retains the centered pair-preference formula and positive-only recommendation use from decisions 0005–0008; it does not wire the proposed adjusted-cosine similarity or approve provider-derived exports.

## Recommendation export

The graph builder writes `graph-compact-v2` and, unless disabled, `graph-legacy-v2`. Both have `role: "recommendation"` and the same `graphId`. Every anime-pair edge carries positive integer co-rater `support`. `semantics` names the current pair weight (`centered-pair-preference-mean-v1`), support scope (`co-raters-after-selection-v1`), and use (`positive-only-v1`). These names prevent a pair-preference weight from being read as correlation or adjusted cosine.

`config` records the rating selection policy, unsigned 32-bit seed, per-user cap, pair work/key budgets, support threshold, output edge cap, and per-anime neighbor limit. `truncation` records input and selected ratings, omitted ratings and pair visits, candidate/eligible/selected pairs, and support/neighbor/output exclusions. The separate build report still carries runtime, peak process RSS, and coverage fractions; it now repeats `graphId` and `datasetSha256` so it can be matched to a graph. A capped graph remains an approximation of the full rating set, even if its selected pair statistics are exact.

`dataset.sha256` is a canonical SHA-256 over source and sorted anonymized user/rating content (user ID, anime ID, title, raw score, and centered score). It omits `generatedAt` and row order. The ratings exports carry the same `datasetSha256`; the Python trainer checks that declared identity before using a v2 graph. This is a content identity produced before compact rating rounding, not a byte hash of either JSON file and not a signature. Readers validate the digest's form and cross-artifact equality; they do not recompute it from a ratings file. `graphId` hashes the compact recommendation metadata and node/edge arrays without `generatedAt`; the legacy representation carries that same ID. The browser checks the declared IDs and provenance link but does not recompute either graph hash. An artifact publisher must keep the generated set together.

## Visualization artifact

`sync:web` derives `graph-explorer.compact.json` as `graph-compact-v2` with `role: "visualization"`, its own `graphId`, and `sourceGraphId` equal to the recommendation graph ID. It ranks user-anime and anime-anime edges separately by absolute weight with stable index ties when limits apply, keeps at most 2,500 and 8,000 respectively, remaps referenced nodes, and records those limits and exclusion counts. This is a display sample, not the neighborhood used for ranking or training. The synthetic demo uses smaller 10/10 limits to exercise the separation. A legacy-only v2 build is converted to compact in the sync step before sampling; both compact and legacy-only sync paths are exercised with temporary invented data. If both source formats are present, sync refuses mixed versions or mismatched IDs instead of silently preferring a stale compact graph.

The browser requires the matching explorer for a v2 recommendation graph and rejects missing files, wrong roles, unsupported semantics, or mismatched source ID, dataset identity, and configuration. Recommendations and the Python trainer reject visualization-role graphs. The browser and trainer still read existing `graph-compact-v1` and unversioned legacy graphs with their old pair semantics. For a v1 main graph, the browser may fall back to the main graph when the old explorer file is absent. Mixed v1/v2 metadata and unknown formats fail clearly. Existing model artifacts are unchanged; they have not been retrained or bound to the new graph ID.

## Verification and limits

Invented fixtures cover both producer formats, both sync paths, support and count reconciliation, malformed v2 metadata, old-reader compatibility, trainer dataset-header matching, and smaller explorer loading. The existing hand-computed, shuffled-input, bounded-selection, signed-edge, and no-NaN/reference tests remain the M3 mathematics gate. This format work does not establish ranking quality or production capacity. The dataset and graph IDs identify generated artifacts, but are not an authenticity or tamper-proof check. M5 must compare any future neighborhood semantics on a split-first benchmark, and decision 0001 still holds provider collection, training, and publication.
