# 0014 — Raw-interaction split manifest

**Status:** Protocol committed as `ed23ce2` before implementation and fixture results on 2026-09-25. The synthetic loader, manifest, CLI, and partition tests passed; M5.1 completion is recorded in the living plan.

## Boundary and input

Split raw user–anime scores before centering, graph construction, popularity counts, model fitting, or metric calculation. Accept the existing legacy and `ratings-compact-v1` exports only through their raw-score fields; ignore their already centered fields. Also accept a small `raw-interactions-v1` input with explicit `timestampBasis`. This is a restricted local evaluation input, never a web or release artifact. The current SQLite `fetched_at` and `provider_updated_at` fields and export `generatedAt` do not establish when a person rated or watched a title ([decision 0004](0004-collection-provenance.md)). No current exported ratings format qualifies for a temporal split. Provider-use and public-data holds in [decision 0001](0001-provider-data-permissions.md) remain in force.

Validate user IDs, positive integer anime IDs, finite raw scores, and all referenced compact indexes. Combine input blocks for the same user. Deduplicate identical `(user ID, anime ID, raw score, verified event time)` rows **before** allocation. Reject conflicting duplicate user–anime rows because row order and fetch time cannot choose a trustworthy winner. Reject malformed or normalized-only rows rather than silently discarding them. Empty users do not create interaction IDs.

## Fixed membership

An interaction ID is SHA-256 of the UTF-8 bytes `wasiw-interaction-v1\n` plus compact JSON `[userId, animeId]` (Unicode unescaped). The identity digest hashes sorted IDs, one per line. A separate raw-content digest hashes sorted `[interactionId, rawScore, canonicalEventTimeOrNull]` records. No plain user IDs or scores are written to the manifest. Membership depends only on stable IDs, never scores, titles, centered values, input order, or metadata. A changed score keeps membership IDs fixed but changes the content digest.

The default `auto` policy uses `seeded-per-user-v1` for present exports and for raw input without verified event times. For each user with at least three distinct ratings, reserve `max(1, floor(n × 0.20))` each for test and validation, keeping at least one training row. Order a user's rows by SHA-256 of `wasiw-split-seeded-v1\n` plus compact JSON `[seed, userId, animeId]`; take test first, validation next, and train the rest. Users with fewer than three distinct ratings stay entirely in train. The seed defaults to 42 and is recorded. The policy is a seeded per-user holdout, **not** a temporal or independent-user evaluation; it cannot establish prospective quality.

Only `raw-interactions-v1` with `timestampBasis: "verified-rating-or-viewing"` and a valid event time on every row can use `verified-event-time-v1`. `auto` selects it when that evidence is complete; an incomplete verified-time claim fails instead of silently falling back. An explicit temporal request without the verified basis also fails. For each eligible user, sort by actual UTC event time, allocate the latest rows to test and the immediately preceding rows to validation, and reject ties that cross a partition boundary. A caller-supplied evidence label is necessary but not independently sufficient for real provider use: a reviewed source mapping and permission record must precede any non-synthetic temporal claim. Fetch, update, import, and generation times never substitute for event times.

The manifest records format/policy/seed, ratios, minimum history, input format, timestamp basis, identity/content digests, unique count, dropped identical duplicate count, users with holdouts, and sorted train/validation/test ID arrays. The CLI creates a new file exclusively, refuses overwrites and public/release output paths, and logs counts without user IDs or scores. `--check` compares a generated manifest against an existing pinned fixture without modifying it. `partition_snapshot` validates the exact format, identity, disjoint membership, coverage, and content fingerprint before returning raw partitions; M5.2 owns fitting preprocessing and models solely from the train partition. M5.3 owns explicit model/graph leakage assertions. Existing `ml/train_graph_mf.py`, Optuna, and LightGCN metrics still use an older normalized/full-graph path and are **not** M5 evidence.

## Predeclared synthetic acceptance

Pin an invented 13-unique-interaction fixture with one identical duplicate, three users eligible for holdout, and one one-rating user. At default ratios expect 7 train, 3 validation, and 3 test IDs, with exact golden manifest equality. Reversing input order and changing scores or normalized fields must leave membership unchanged; a score change must change only the content digest. Verify identical duplicate collapse, conflicting duplicate rejection, malformed/raw-missing/reference failures, sparse-user handling, and no overwrite on failure. Verify temporal ordering on invented verified event times, refusal for fetch/update times or incomplete event times, and boundary-tie rejection. Run only synthetic or mocked inputs; do not train, fetch, or publish provider-derived artifacts.

## Fixture result

`npm run split:fixture:check` matches the checked-in golden manifest: 13 unique invented interactions after one identical duplicate, with 7 train, 3 validation, and 3 test IDs. The six focused Python tests verify exact partition coverage, stable IDs after row reordering and score changes, raw-score-only legacy/compact loading, content-fingerprint change on score edit, sparse users, temporal evidence and ordering, tied-boundary rejection, invalid/conflicting rows, tampered manifests, exclusive CLI creation, read-only check, and refusal of public output. This verifies split mechanics only. No preprocessing, graph, model, tuning, or real-user metrics were produced.
