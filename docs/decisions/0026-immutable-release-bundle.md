# 0026 — Immutable release bundle identity and compatibility

**Status:** M8.1 protocol fixed on 2026-09-28 before generating a release manifest. This authorizes only synthetic fixture work. Provider publication, model promotion, deployment, and remote rollback remain held by decisions 0001, 0002, and 0024.

## Contract

A new opt-in `release-manifest-v1` binds a **versioned** `data-v...` tag and a content-derived `bundleId` to one complete set of plain JSON artifact bytes. `data-latest` and other mutable tags are invalid. The manifest records the graph's declared dataset scope/source/SHA-256; exact byte hashes, lengths, schema formats, and graph IDs for a v2 recommendation neighborhood and its linked v2 explorer; an independent `anime-catalog-v1` identity file with sorted anime ID/title pairs and its byte hash; and an optional compact model's byte hash, schema, item count, and catalog mapping hash. The catalog identity file covers the titles the current graph can recommend; it does not claim complete genre/score metadata, which remains M6.4 work.

The producer recomputes recommendation and explorer graph IDs from their v2 content, validates the browser artifact contracts, compares dataset provenance and explorer source/config/semantics, and requires the catalog ID/title pairs to equal the recommendation graph's full anime map. Every model item must be in that map with exactly the same title; a partial model is allowed but its mapped/total catalog counts are recorded. A manifested compact model must declare `datasetSha256` equal to the graph's declared dataset ID; older models without that optional field remain readable by v1 clients but cannot join a new manifest. The producer calculates SHA-256 over the exact plain file bytes and an anime-map digest over compact JSON of pairs sorted by numeric anime ID. The manifest's `bundleId` hashes the deterministic `JSON.stringify` payload in contract field order excluding that self-referential field. This is a content identifier and compatibility check, not a signature, source-rights decision, or proof that the declared graph or model dataset identity was recomputed from private ratings.

Each non-genesis manifest names one separate **last-known-good** bundle by versioned tag, bundle ID, and exact manifest-byte hash. Validation requires the prior manifest and all prior assets to remain available and internally compatible in a separate directory. A genesis manifest requires an explicit fixture-only bootstrap mode; an absent previous bundle is otherwise a failure. Reject missing/corrupt assets, malformed or unsupported schemas, model title/ID drift, stale catalog/graph/explorer links, changed prior manifest bytes, repeated tags, and a previous bundle that resolves to the current directory. A writer refuses an existing manifest file so a named bundle is not silently overwritten.

This contract applies to synthetic local bundles first. The ignored, reproducible demo fixture derives its versioned tag from all generated asset hashes; it may be regenerated locally, while the named bundle writer refuses to replace an existing manifest. The current `data-latest` fetch, `sync:web`, and browser gzip loader are legacy paths; M8.2 must fetch the manifest and install a verified complete bundle atomically before runtime uses it. M8.3–M8.5 own publication allowlisting, promotion/deployment, and hosted verification; M8.7 owns practiced recovery. No production asset is fetched, republished, or removed to test M8.1.
